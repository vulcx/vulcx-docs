An API key is **optional** on REST calls to the Vulcx API (`https://api.vulcx.xyz`) — `/quote`,
`/swap`, `/instructions`, and `/price` all work with no key. Without one, you're on a small shared
anonymous budget of 2 cost units/second; send a key and you get your plan's own budget — 20 cost
units/second on Free, more on paid plans. Keys
look like `vulcx_` followed by a long hex string, and you send them in the standard `Authorization:
Bearer` header (or as a `?key=` query parameter).

<Note>
The **WebSocket stream is the exception**: `GET /api/v1/stream` always requires a key, passed as
`?key=` since a browser WS handshake can't carry custom headers, and the key's plan must include
stream connections. See [WebSocket streaming](#websocket-streaming) below.
</Note>

<Note>
Getting a key is worthwhile even on Free: anonymous access is capped at 2 cost units per second,
burst 20, against the 20/40 a Free key gets (see [Rate limits](/api-reference/rate-limits)), and a
key is what gives you your own budget rather than a bucket shared with every anonymous caller on
your IP. Paid plans raise the budget and add stream connections.
</Note>

## Get an API key

<Steps>
  <Step title="Create a key">
    Sign in to the portal with Google or GitHub and create a key. It works against mainnet
    immediately on the Free plan; upgrade there when you need a larger budget or the stream.

    <Card title="Open the Vulcx Portal" icon="key" href="https://portal.vulcx.xyz" horizontal>
      Keys, per-key fee defaults, usage and earnings.
    </Card>

    Need something the plans don't cover? Ask on [Telegram](https://t.me/vulcxsupport).
  </Step>
  <Step title="Store it as an environment variable">
    Never hard-code a key in source. Keep it in an environment variable:

    ```bash
    export VULCX_KEY="vulcx_your_key_here"
    ```
  </Step>
</Steps>

## Authenticate a request

Send your key in the `Authorization` header on every request:

<CodeGroup>
```bash cURL
curl "https://api.vulcx.xyz/api/v1/quote?inputMint=So11111111111111111111111111111111111111112&outputMint=uSd2czE61Evaf76RNbq4KPpXnkiL3irdzgLFUMe3NoG&amount=1000000000&swapMode=ExactIn" \
  -H "Authorization: Bearer $VULCX_KEY"
```

```typescript TypeScript
const res = await fetch(
  "https://api.vulcx.xyz/api/v1/quote?inputMint=So11...&outputMint=uSd2...&amount=1000000000&swapMode=ExactIn",
  { headers: { Authorization: `Bearer ${process.env.VULCX_KEY}` } },
);
```

```python Python
import os, requests

res = requests.get(
    "https://api.vulcx.xyz/api/v1/quote",
    params={
        "inputMint": "So11111111111111111111111111111111111111112",
        "outputMint": "uSd2czE61Evaf76RNbq4KPpXnkiL3irdzgLFUMe3NoG",
        "amount": "1000000000",
        "swapMode": "ExactIn",
    },
    headers={"Authorization": f"Bearer {os.environ['VULCX_KEY']}"},
)
```
</CodeGroup>

## SDK

The [SDK](/sdk/configuration) takes the key directly — you don't set headers yourself.

```typescript SDK
import { VulcxSDK } from "@vulcx/sdk";

const sdk = new VulcxSDK({ apiKey: process.env.VULCX_KEY });
```

## WebSocket streaming

Browsers can't set custom headers on a WebSocket connection, so the streaming endpoint accepts the
key as a `key` query parameter instead:

```text
wss://api.vulcx.xyz/api/v1/stream?key=vulcx_your_key_here
```

The stream is part of paid plans from Starter up, and each plan caps how many connections the
account may hold at once — see [Rate limits](/api-reference/rate-limits#stream-connections).
Free-plan keys keep one connection until 14 November 2026.

## Keep your key secret

<Warning>
A key grants access under your account's rate limits. Treat it like a password.
</Warning>

- **Server-side keys stay on the server.** Don't commit keys to git or ship them in a public repo.
- **Browser usage exposes the key** in client code. For client-side embeds, use a key you've
  provisioned for that purpose and rotate it if it leaks.
- **Rotate compromised keys** by requesting a new one and retiring the old.

## Errors

| Status | Meaning |
|--------|---------|
| `401 Unauthorized` | No API key was provided, on an endpoint that requires one — only the WebSocket stream (`/api/v1/stream`) requires a key; REST calls with no key succeed anonymously instead. |
| `403 Forbidden` | The key is invalid, disabled, or revoked — or, on the stream, its plan does not include stream connections (`STREAM_NOT_IN_PLAN`). |
| `429 Too Many Requests` | On the stream: the account already holds its plan's connections (`STREAM_LIMIT`). |

The SDK surfaces these as `AuthError` — see [SDK error handling](/sdk/error-handling). For
throughput limits — including the tighter anonymous-tier limit — and the `429` response, see
[Rate limits](/api-reference/rate-limits).
